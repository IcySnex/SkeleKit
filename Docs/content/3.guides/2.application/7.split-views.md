A split view is the native `UISplitViewController`: a container that arranges two or three navigation stacks side by side and collapses them into one on compact size classes. In SkeleKit it is declared with `SplitViewBuilder` and can be the app shell, a tab destination, or a sidebar destination.

## App shell

```csharp [Main.cs]
SkeleApplication.CreateBuilder()
    .SplitView(split => split
        .Primary<FolderView>()
        .Secondary<NoteView>())
    .Build()
    .Run(args);
```

`Primary<TView>()` installs the leading column and `Secondary<TView>()` the detail column. Each column gets its own navigation stack, root page, toolbar, title, search and appearance settings, exactly like a tab. A split view requires both; validation fails at `Build()` when one is missing.

`Style(SplitViewStyle.TripleColumn)` adds a middle column declared with `Supplementary<TView>()`. `Compact<TView>()` replaces the page shown while the split view is collapsed. On iOS 26 and later, `Inspector<TView>()` adds the trailing inspector column; earlier versions skip the declaration. `SplitViewStyle` and `SplitViewColumn` live in `SkeleKit` and are available on every platform target.

## Tabs and sidebar destinations

Any tab destination can be a split view while the other tabs keep their single-stack behavior:

```csharp
.Tabs(tabs => tabs
    .Tab<HomeView>("Home", "house")
    .Split("Notes", "rectangle.split.2x1", split => split
        .Primary<NotebooksView>()
        .Secondary<NotesListView>()));
```

`SidebarBuilder.Split(...)` declares a sidebar-only destination the same way. A split view can't be nested inside a tab group.

Pass `TabPlacement.Hidden` when the destination should never appear in the tab bar or sidebar and is only reached programmatically:

```csharp
.Split(
    "Notes",
    "rectangle.split.2x1",
    split => split
        .Primary<NotebooksView>()
        .Secondary<NotesListView>(),
    TabPlacement.Hidden);

// later
await navigator.SelectTabAsync("Notes");
```

## Navigation

Every column owns an independent navigation stack. `NavigationColumn(...)` chooses which one the parameterless navigator calls use; the default is `Secondary`:

```csharp
await navigator.PushAsync(new NoteViewModel(note)); // navigation column
```

The column overloads address a stack directly:

```csharp
await navigator.PushAsync(
    SplitViewColumn.Primary,
    new FolderViewModel(folder));

await navigator.PushAsync(
    SplitViewColumn.Secondary,
    new NoteDetailViewModel(note));

await navigator.PopAsync(SplitViewColumn.Secondary);
await navigator.PopToRootAsync(SplitViewColumn.Primary);
```

When the split view is collapsed — an iPhone in portrait, for example — column calls route to the visible compact stack, so pushes and pops still land where the user is looking. When no split view is active, such as while another tab is selected, the column overloads throw. Tapping a selected tab pops the navigation column's stack.

## Column visibility

Inject `ISplitView` to show, hide, or query columns:

```csharp
ISplitView split = ...;

split.Hide(SplitViewColumn.Primary);
split.Show(SplitViewColumn.Primary);

if (split.IsCollapsed)
    return;

// visibility queries and toggling require iOS 26 or later
if (OperatingSystem.IsIOSVersionAtLeast(26))
    split.Toggle(SplitViewColumn.Primary);
```

`Show` and `Hide` use UIKit's adaptive presentation and are available from iOS 18. `IsShowing` and `Toggle` depend on the iOS 26 visibility API and throw `PlatformNotSupportedException` earlier. Asking for the inspector column before iOS 26 also throws.

## Badges

A split destination is a single tab. Only the navigation column's root page drives `TabBadge`; badges set by the other columns are ignored, so assign the badge to the page the user considers the tab's primary surface.

## Native configuration

`ConfigureNative` runs after SkeleKit installs the columns and exposes the raw controller for display mode, split behavior, gestures, column widths and delegates:

```csharp
.SplitView(split => split
    .Primary<FolderView>()
    .Secondary<NoteView>()
    .ConfigureNative(native =>
    {
        native.PreferredDisplayMode = UISplitViewControllerDisplayMode.OneBesideSecondary;
        native.PreferredSplitBehavior = UISplitViewControllerSplitBehavior.Tile;
        native.PreferredPrimaryColumnWidthFraction = 0.3;
    }))
```

## Limits

A split view is a destination-level container. UIKit cannot push it onto a navigation stack, so it can't be a page inside a stack, and SkeleKit doesn't build it for modal presentation. Use it as the shell or as a tab/sidebar destination. For two panes inside a single page, use the layout panels instead.
