Use `ObservableCollection<T>` when collection membership changes after the view appears:

```csharp
public ObservableCollection<Contact> Contacts { get; } = [];

void Add(Contact contact) => Contacts.Insert(0, contact);
void Remove(Contact contact) => Contacts.Remove(contact);
void MoveToTop(Contact contact) => Contacts.Move(Contacts.IndexOf(contact), 0);
```

SkeleKit coalesces source changes into animated native snapshots. Mutate the collection on the main thread. Bind item properties through `INotifyPropertyChanged` when the row stays in place but its displayed values change.

See [data and templates](/guides/collections/data-and-templates) for the distinction between item identity, membership changes, and bound property changes.

## Taps and highlights

`ItemCommand` runs with the tapped item:

```csharp
new CollectionView<Contact>
{
    ItemsSource = viewModel.Contacts,
    ItemTemplate = static () => new ContactRow(),
    Layout = CollectionLayout.List(),
    ItemCommand = viewModel.OpenContactCommand,
    RetainsHighlight = true
};

sealed class ContactRow : ItemView<Contact>
{
    public ContactRow()
    {
        Background = Colors.SecondaryBackground;
        HighlightBackground = Colors.Indigo.WithAlpha(0.12);
    }
}
```

`HighlightBackground` belongs to the item template and defaults to the system gray. Set it to `null` for an item with no visual highlight. Without a selection binding, `RetainsHighlight` controls whether the tapped row stays highlighted until the page appears again; disable it for cards or controls where a retained highlight would be misleading.

The collection checks `ItemCommand.CanExecute(item)` before UIKit highlights or selects the item. Returning `false` prevents the pressed appearance and command execution for the collection. Set or bind `IsEnabled` on an individual `ItemView` to independently disable that rendered row, including its pressed appearance.

## Selection

Bind exactly one of `SelectedItem` or `SelectedItems`:

```csharp
new CollectionView<Contact>
{
    ItemsSource = viewModel.Contacts,
    ItemTemplate = static () => new ContactRow(),
    Layout = CollectionLayout.List(),
    SelectedItem = Bind(vm => vm.SelectedContact)
        .TwoWay((vm, value) => vm.SelectedContact = value),
    ShowsSelectionCheckmark = true
};
```

`SelectedItem` is single selection: a tap replaces the selection, and a two-way binding pushes the tapped item to the source. Setting it in the ViewModel selects the matching row on first paint, and the selection survives snapshots, scrolling, and page appearances.

`SelectedItems` is multiple selection: taps toggle rows, and mutating the bound collection moves the selection:

```csharp
public ObservableCollection<Contact> SelectedContacts { get; } = [];
```

Give `SelectedItems` an `ObservableCollection` so taps can write back. Bind either selection property, never both.

By default taps select whenever they press a row. Set `SelectsOnlyWhileEditing = true` when a normal tap should only activate and selection belongs to an edit button:

```csharp
SelectedItems = viewModel.SelectedContacts;
SelectsOnlyWhileEditing = true;
IsEditing = Bind(vm => vm.IsEditing)
    .TwoWay((vm, value) => vm.IsEditing = value);
```

With that, normal taps run `ItemCommand` and keep the transient highlight behavior, while edit mode toggles the selection circles. The bound selection is preserved when editing ends; clear it in your own Done command if the page should forget it.

Reference identity applies, like everywhere else in collections.

`ShowsSelectionCheckmark` draws a trailing checkmark on selected rows while not editing, tinted with the app tint; the edit-mode circles take over while editing.

## Accessories

Item accessories are native affordances driven by the item, separate from collection selection:

```csharp
sealed class PaletteRow : ItemView<Palette>
{
    public PaletteRow()
    {
        Accessories.Add(new CheckmarkAccessory
        {
            IsVisible = Bind(palette => palette.IsSelected),
            Tint = Colors.Teal
        });
    }
}
```

`CheckmarkAccessory` and `DisclosureAccessory` need no configuration. `DetailAccessory` adds the info button and runs its command with the row's item when tapped:

```csharp
Accessories.Add(new DetailAccessory
{
    Command = Bind(item => item.InfoCommand)
});
```

`LabelAccessory` shows a trailing string such as a count:

```csharp
Accessories.Add(new LabelAccessory
{
    Text = Bind(item => item.Count),
    TextStyle = TextStyle.Footnote,
    Tint = Colors.SecondaryLabel
});
```

Every accessory accepts `IsVisible`, `Tint`, and `Display`. `IsVisible` binds like any control property; a hidden accessory takes no layout space, and the row reflows like a native list row. `Display` picks `Always`, `WhenEditing`, or `WhenNotEditing`. A checkmark is green unless `Tint` overrides it.

## Empty state

`EmptyView` replaces the collection content while the active source has no items. It is a SkeleKit view, so it can contain a retry command or progress state rather than only text.

## Scrolling

`Scrolled` reports the vertical offset. Call `ScrollTo(item, position, animated)` to bring an existing item into view:

```csharp
contacts.ScrollTo(
    selectedContact,
    ScrollPosition.Center,
    animated: true);
```

The requested object must be the same instance present in the source. `ScrollPosition.Top`, `Center`, and `Bottom` choose its alignment.

## Loading near the end

Set `LoadMoreCommand` and `LoadMoreThreshold` to request another page before the user reaches the final item. The command fires once for a given item count. Adding results enables another request when the new end approaches; leaving the count unchanged prevents an immediate loop.

Keep a ViewModel loading flag and make the command's `CanExecute` reflect it so concurrent requests cannot overlap.

Pull-to-refresh, swipe actions, context menus, and edit mode are covered in [refresh and editing](/guides/collections/refresh-and-editing).
