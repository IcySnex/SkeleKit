SkeleKit bindings work with ordinary `INotifyPropertyChanged` objects and `ICommand`. There is no required ViewModel base class. CommunityToolkit.Mvvm is convenient, but the binding system does not depend on it.

For command execution and gesture-backed actions, see [commands, menus, and gestures](/guides/foundations/commands-menus-and-gestures).

```csharp
public sealed partial class ProfileViewModel : ObservableObject
{
    [ObservableProperty]
    string displayName = "Ada";

    [ObservableProperty]
    bool notificationsEnabled = true;
}
```

```csharp
[Page]
public sealed class ProfileView : ContentView<ProfileViewModel>
{
    public ProfileView(ProfileViewModel viewModel) : base(viewModel)
    {
        Content = new StackPanel
        {
            Spacing = 12,
            Children =
            {
                new Label
                {
                    Text = Bind(model => model.DisplayName)
                },
                new Switch
                {
                    IsOn = Bind(
                        model => model.NotificationsEnabled,
                        static (model, value) => model.NotificationsEnabled = value)
                }
            }
        };
    }
}
```

The first binding is one-way: property changes update the label. Supplying a setter makes the second binding two-way, so both ViewModel changes and user interaction stay synchronized.

## Converting values

Provide a formatter when the control and source use different representations:

```csharp
Text = Bind(
    model => model.Progress,
    value => $"{value:P0}");
```

A two-way converted binding also takes a parser. This is useful for numeric text fields, but validation still belongs in the ViewModel or submission flow.

## Update triggers

Two-way bindings update on every control change by default. Text controls can defer the write until focus leaves:

```csharp
Text = Bind(
    model => model.Email,
    static (model, value) => model.Email = value)
    .On(UpdateTrigger.FocusLost);
```

`UpdateTrigger.Explicit` prevents automatic writes. Use it when a form commits through a separate action.

## Other binding modes

- `BindOnce` reads when the context attaches and does not subscribe to later changes.
- `BindToSource` lets the control write without refreshing from subsequent source changes.
- `BindingFactory.BindPath` observes a nested object and its leaf property, including replacement of the intermediate object.

Binding paths must be plain property access. Calls, indexers, casts, and arbitrary expressions are rejected because SkeleKit derives subscriptions from the captured lambda text instead of using reflection or compiled expression trees.

## Lists

List-valued properties accept arrays, `List<T>`, `ObservableCollection<T>`, collection expressions, or a binding through `BindableList<T>`. An `ObservableCollection<T>` updates live controls such as `Picker` and `CollectionView` as items are added, removed, moved, or replaced.

The [collection data and templates guide](/guides/collections/data-and-templates) shows how item bindings behave with recycled cells.

## Binding context

Bindings resolve against `BindingContext`. Panels pass their inherited context into their descendants. Set a local context when a reusable subtree needs another source; removing that local value makes it inherit from its parent again.
